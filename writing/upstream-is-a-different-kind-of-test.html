Upstream is a different kind of test

A patch that works in my repository answers “can I make this work?” A patch accepted into somebody else's library has to answer a harder question: “what may everyone else safely assume after this lands?”

Claim. Upstream contribution is valuable because it changes the unit of correctness. Local code can optimize for one experiment or environment; shared infrastructure must define behavior around unsupported cases, compatibility surfaces, regression boundaries, and future callers you do not control.

The patches look unrelated

I have merged patches into MatGL, MLX-LM, Alloy, uutils/coreutils, and uutils/parse_datetime. The surface areas range from MC-dropout uncertainty to a learnable activation, token sampling defaults, EIP-712 recursion, timezone output, negative Unix timestamps, AM/PM grammar, and a two-letter timezone alias.

The useful pattern is not the technology list. It is what had to become explicit before each change was safe to share.

1. A feature needs a failure contract

The MatGL MCDropoutWrapper began as research machinery. Upstreaming forced model-state restoration, supported-architecture boundaries, batching semantics, and explicit rejection of configurations without a compatible dropout site. The library could not inherit the experiment's unstated assumptions.

That changed how I think about reusable ML infrastructure: unsupported behavior should fail loudly at the abstraction boundary, not produce plausible tensors with unclear meaning.

2. Forward values are not the whole API

The SoftExponential patch looked numerical but exposed a deeper contract. A Python branch over a learned tensor could return reasonable forward values while disconnecting the parameter from the differentiable program. The regression tests therefore had to include finite, nonzero gradients—not just output equality.

Shared ML code taught the same lesson systems libraries do: hidden state transitions count as API even when the type signature does not mention them.

3. Defaults are behavior

The MLX-LM XTC fix changed only three defaults, but the old combination could mask almost the entire candidate token distribution when a user enabled one control and left its companion threshold untouched. The correction had to land consistently in the sampler factory, CLI, and server.

A default is not documentation. It executes.

4. The specification can contain distinctions the algorithm erases

Alloy's EIP-712 bug came from treating self-reference and mutual recursion as the same graph phenomenon. The standard allowed one; the runtime representation still could not support the other. The fix needed two cycle policies tied to two operations, with tests proving both the new legal case and the still-illegal neighbor.

5. Compatibility is made of tiny promises

The uutils patches were the most humbling. Re-zoning EST into the caller's local timezone, flooring @-1.5 to -2, parsing 12:00 PM without orphaning the suffix, and accepting UT all look small. They are small. They are also observable contracts that scripts and users rely on.

Line count is a poor proxy for how much behavior a patch changes.

What upstream acceptance does—and does not—mean

A merge is useful third-party evidence: maintainers accepted the patch into a codebase with its own tests, conventions, compatibility commitments, and review process. That is stronger than self-certification.

It is not a proof of correctness. Maintainers can miss bugs; test suites have blind spots; upstream constraints can favor compatibility over ideal design. The point is not that external review is infallible. The point is that it introduces an independent set of incentives and assumptions.

The habit I kept

Before proposing a change now, I try to write the sentence a downstream caller should be able to rely on after merge. Then I write the neighboring sentence that must remain false.

For recursion: self-reference can canonicalize; mutual recursion is still rejected. For uncertainty: supported readouts can produce stochastic samples; calibration is not promised. For timestamps: negative fractional seconds floor compatibly; the numeric representation remains precise. For sampling: enabling XTC without an explicit threshold should not create a degenerate distribution; 0.1 is not claimed to be universally optimal.

A good patch expands the set of safe assumptions without quietly expanding the set of claims.
