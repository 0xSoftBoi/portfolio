A research primitive should outlive the result that motivated it

I needed uncertainty estimates for one active-learning experiment. The useful outcome was turning that need into a reusable MatGL primitive—and then being willing to discover that the uncertainty itself was poor.

Claim. Research code becomes more valuable when the mechanism is separated from the conclusion. I upstreamed a general MC-dropout uncertainty wrapper into MatGL because the capability—stochastic uncertainty estimation on pretrained materials models—was reusable even if any particular active-learning hypothesis later failed.

The wrong unit of reuse is the experiment

The original need was local: rank candidate materials using a mean prediction μ and uncertainty σ. It would have been easy to leave dropout toggling, batching, model-state management, and acquisition logic inside a benchmark script.

Instead I pulled the uncertainty mechanism into a library boundary. MCDropoutWrapper takes a pretrained MatGL model, injects or activates dropout only where the supported readout architecture allows it, returns per-structure mean and standard deviation, and restores the model to evaluation mode after the call—even if inference throws.

That separation turned “my benchmark needs σ” into “MatGL users can ask a supported pretrained model for a stochastic estimate without rewriting model internals.” The patch merged upstream as PR #801.

What had to become explicit

A reusable primitive has to surface the assumptions an experiment can hide.

Where stochasticity lives. The wrapper keeps the graph-convolutional backbone deterministic and re-enables stochasticity in the readout. That avoids perturbing unrelated evaluation-time state and makes the scope legible.

Default models may have no dropout module. CHGNet can expose an identity placeholder when configured with zero final dropout. The wrapper replaces that supported site with real dropout rather than requiring retraining.

Not every architecture has a compatible injection point. Intensive M3GNet readouts are supported; configurations whose readout has no compatible dropout site fail explicitly rather than pretending to provide Bayesian uncertainty.

State cleanup is part of correctness. The model returns to eval() after inference. A convenience wrapper that leaves a pretrained model in stochastic training mode would be a dangerous abstraction.

Reusable ML infrastructure is mostly the work of making hidden experimental assumptions impossible to ignore.

Performance changed what was practical

The application layer later optimized the same structure: when only the readout is stochastic, the expensive deterministic representation can be computed once and the cheaper head replayed across MC passes. The active-materials repository reports roughly 16.5× faster inference at 20 passes on an RTX 3080 with numerical equivalence to the naive loop.

That benchmark is hardware- and implementation-specific, so I do not treat 16.5× as a universal MatGL property. The general idea is more durable: if epistemic sampling perturbs only the head, recomputing the entire backbone is wasted work.

Then the research result got worse

The later calibration study on matbench_perovskites found that this readout-level MC-dropout σ was anti-correlated with absolute error. In that benchmark, the mean prediction did the useful ranking work; the uncertainty did not.

That negative result made the upstreaming decision more—not less—interesting. The wrapper does not encode a claim that MC dropout is calibrated. It exposes a mechanism so users can measure whether it is calibrated for their model and task.

A brittle research artifact would have coupled “MC dropout exists” to “MC dropout improves my UCB result.” A better primitive survives the falsification of the second sentence.

The strongest counterargument

Upstream libraries should be conservative about adding uncertainty APIs because users can mistake a standard deviation for a trustworthy posterior. I agree. A reusable mechanism can increase misuse if its semantics are oversold.

The right answer is not to hide stochastic inference inside research repos; it is to keep the library contract narrow. The wrapper provides samples, means, and standard deviations. Calibration and downstream decision quality remain empirical responsibilities of the caller.

What I learned from the merge

The upstream patch was larger than the core idea because maintainable infrastructure needs behavior around the happy path: supported-model boundaries, batching, shape guarantees, cleanup, deterministic-backbone behavior, exceptions, and tests. PR #801 landed with 15 targeted tests across CHGNet and M3GNet scenarios.

That is the part of open source I value most. A research notebook asks whether an idea works once. A library patch asks what another person should be allowed to assume about it.

The experiment owns the conclusion. The library should own only the mechanism it can actually guarantee.

What this does not establish

Boundary. Upstream acceptance establishes that the implementation met MatGL's review and test bar; it does not establish that MC dropout is calibrated, optimal, or appropriate for every MatGL model. The ~16.5× speed measurement is reported from the application repository on one RTX 3080 configuration, not a universal performance guarantee.
