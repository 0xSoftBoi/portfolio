Recursion is not one kind of cycle

A graph algorithm can be locally correct and still reject valid programs when the specification gives different meanings to different cycles.

Claim. Protocol implementations should encode semantic distinctions from the specification directly rather than compressing them into a generic graph rule. In EIP-712, self-referential types are supported, while some internal resolution paths cannot represent arbitrary recursive values. Treating every cycle as equivalent caused Alloy to reject legal canonical type encoding.

The graph said “cycle.” The specification said “valid.”

A type such as Node(uint256 value, Node[] children) contains a self-edge in its dependency graph. Alloy's canonicalization path used dependency logic that interpreted that self-edge as making the primary component dependent on itself. The primary-component iterator then became empty, and canonicalization failed before it reached a more meaningful semantic decision.

The awkward part is that another Alloy path really does need stricter behavior: resolving into a concrete DynSolType cannot represent the same recursive structure. So “allow cycles” would have been just as wrong as “reject cycles.”

The bug was not missing cycle detection. It was using one definition of a cycle for two operations with different representational limits.

The fix split semantics by operation

The merged patch made self-edges irrelevant when determining the non-dependent primary type, allowing a recursive struct to remain a valid primary component. It then separated cycle checks into strict and permissive variants.

The permissive path is used for linearize and encode_type, where EIP-712 canonical type strings can represent legal self-reference. The strict path remains in resolve, where building a concrete runtime type still cannot represent recursive values. Cycles between distinct types remain rejected.

That distinction also kept the limitation visible: TypedData::eip712_signing_hash can still return CircularDependency for self-referential values because data encoding eventually needs the strict resolver. The patch did not pretend to solve a representation problem it had not solved.

The tests are the specification in miniature

The regression set covered the exact self-referential reproduction, a recursive primary type with an additional leaf dependency, primary-component selection, encode-type round trips, continued rejection by strict resolution, and continued rejection of mutual recursion. The full alloy-dyn-abi suite passed 194 tests with all features.

Those paired tests matter: a fix for recursion is incomplete unless it proves both the newly legal case and the still-illegal neighbor. Otherwise a permissive patch can merely move the bug boundary.

The strongest counterargument

One could simplify the implementation by making every path use the same recursive representation. That may ultimately be a cleaner architecture, but it is a larger change. The patch addressed the concrete standards mismatch without pretending the runtime resolver supported recursive values.

That is often the better correctness trade: separate the semantic operations now, then expand representation only when the rest of the system can honor it end to end.

The general rule

Graph vocabulary can hide domain meaning. “Cycle,” “dependency,” and “recursive” sound interchangeable until a protocol defines one form as legal syntax, another as invalid schema, and a third as unrepresentable runtime data.

When the specification distinguishes two shapes, the implementation should not erase the distinction just because both look identical to a generic algorithm.

What this does not establish

Boundary. The merged patch makes EIP-712 canonical type encoding permissive for legal self-reference while preserving strict runtime resolution. It does not make all recursive EIP-712 values encodable through every Alloy API.
